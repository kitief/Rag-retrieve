fix(shell): keep the webview origin stable so the theme survives restarts

The theme was saved and then thrown away: WebView2 partitions localStorage by
origin, and the shell launched the backend with `--port 0`, so every start
produced a different `http://127.0.0.1:<port>` and therefore an empty storage
bucket. Light mode, language, the login token and the onboarding flag all reset.

- Remember the port that actually bound in `<data>/app-port.txt` and reuse it.
- Fall back through 47823-47826 when it is taken, and only then to a random one.
- Retry the next candidate when a port fails to become ready, not just when the
  bind probe fails.
- Cache the applied theme (mode + computed variables) and replay it from
  `public/theme-boot.js` in `<head>`, so a light-mode user no longer sees a dark
  flash before hydration.

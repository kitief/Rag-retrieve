# RagVault

> Turn your lecture slides and textbooks into a tutor you can talk to
>
> **Release `beta-v1.0`** · Repository: <https://github.com/kitief/Rag-retrieve>
>
> English | [简体中文](README.md)

RagVault is a study tool for Windows. Drop your PDF slides, PowerPoint decks, Word assignments and Markdown notes into it, and it becomes your own tutor: you can ask questions about the material, get quizzed on it, compress a whole textbook into revision cards, and have a study plan built around the questions you keep getting wrong.

Answers are generated by a cloud LLM (DeepSeek by default). **Embeddings are computed on your own machine** — your documents are never uploaded. Only the handful of passages that actually get retrieved are sent to the model provider.

## 🎯 What it does for you

| What you want | How RagVault does it | Where |
| --- | --- | --- |
| Understand a chapter before an exam | Ask questions about the slides; every answer carries its source (filename + page) | The ask box in a knowledge space |
| Find out whether you actually know it | 20 multiple-choice questions generated from your own material, graded immediately with weak topics listed | The **Quiz** panel on the right |
| Compress a whole textbook into revision cards | Page-by-page structured notes, exportable as a searchable PDF | **AI Notes** at the top |
| Know what to revise next | A Markdown study plan built from the questions you missed in your last 5 quizzes | **Generate Study Plan** on the quiz results screen |
| Keep one course's material together | One knowledge space per course — documents, chats, quizzes and notes never bleed into each other | **New Chat** in the sidebar |
| Swap the model or the provider | DeepSeek and OpenAI are built in; any OpenAI-compatible endpoint works | Settings → API |

In one sentence: **it is not "a chat box with an upload button" — it folds the whole read → practise → patch-the-gaps loop into one window.**

## 🚀 Up and running in 5 minutes

### Install

1. Download `RagVault_1.0.0_x64-setup.exe` from [Releases](https://github.com/kitief/Rag-retrieve/releases/tag/beta-v1.0) (the repository is private, so you need to be signed in to GitHub).
2. Double-click to install. It goes to `%LOCALAPPDATA%\RagVault` and **needs no admin rights**.
3. The installer is not code-signed, so Windows shows "Windows protected your PC" — click **More info** → **Run anyway**. Alternatively, right-click the installer → Properties → tick **Unblock** before running it.

After that, just double-click the desktop icon. No Python, no Docker, no browser.

### Enter an API key

On first launch the settings window opens by itself and stops on the **API** panel (there is no usable model yet). Three steps:

1. **Provider** — `DeepSeek` by default; `OpenAI` or any OpenAI-compatible endpoint also works.
2. **Base URL** — filled in for you when you pick a preset; usually nothing to change.
3. **API key** — grab one from [platform.deepseek.com/api_keys](https://platform.deepseek.com/api_keys) and paste it in.

Then press **Connect**:

- Failed → a **red** strip appears, the model field stays locked and says "Connect first to load the model list".
- Connected → the strip turns **green**, the model field unlocks and is pre-filled with the first model the endpoint advertises.

Finally press **Save**. The key lives in the local database and is never uploaded; next time you open the dialog it is still green and you do not have to reconnect.

> No DeepSeek account? Switch the provider to `OpenAI`, or pick a custom endpoint and point it at any OpenAI-compatible URL and key.

### Register and get in

- First run: click **Create account** and fill in an email, a name and a password. The account only exists in your local database — nothing is verified online.
- After signing in you land **straight back in the knowledge space you were last in**. If you have none yet, it creates one for you and jumps in.
  To start another course, click **＋ New Chat** in the sidebar.

> The login page still says "PDF and PPTX support" — that is old copy. See [Uploading material](#-uploading-material) for the formats that actually work.

## 🗂 Your first knowledge space

A "knowledge space" = one course = one self-contained folder. Each course keeps its own documents, conversations, quizzes and notes, with nothing leaking between them.

Click into any space: **documents on the left, chat in the middle, quiz / wrong-answers panel on the right**. The first time you see "Upload documents, then ask questions." in the middle — drag your slides into the dashed box at the bottom left (or click it to pick files) and wait for the document to go from **Processing** to **Ready**. Then you can ask.

A few habits that pay off:

- **One space per course.** Mixing calculus and modern history makes retrieval blurry.
- **Name files specifically** (`ch03_fourier_transform.pdf` beats `slides.pdf`), because that filename is what the citations show.
- **Keep adding to the same space** — new documents join the existing index automatically. To start over cleanly, use **Clear Knowledge**.

## 🎓 The four things you'll actually do

### ① Ask questions about your material

Type in the box in the middle. **Enter sends**, **Shift + Enter** starts a new line.

The answer streams in as it is written, and **every answer carries its source**: the text contains something like `[Source: ch03_fourier_transform.pdf, Page: 12]`, and under the answer there is a **`2 sources`** button that expands into `filename · p.12` chips.

If the material genuinely does not contain the answer, it says so — "not enough information in your documents" — instead of making something up. That is deliberate: better to admit it does not know.

> While a document is still **Processing** the input box is disabled, with the hint "Your document is still being processed. Chat will be available when it is ready."

### ② Get quizzed on it

The **Quiz** panel on the right has two entries:

| Entry | What it generates | Button |
| --- | --- | --- |
| **Auto Quiz (All Docs)** | A mixed set covering every document in the space | Generate Auto Quiz |
| **Topic Quiz** | Questions only about the topic or chapter you type, e.g. "neural networks" | Generate Topic Quiz |

Both are **20 single-choice questions** (fixed, not configurable). Submit and you immediately see:

- your score (`18/20 correct`)
- for each wrong question: your answer, the correct answer, and an explanation of the passage
- **Needs review:** followed by the weak topics

Every quiz you have taken is collected under **Quiz History** in the sidebar, grouped by knowledge space, each row showing a score ring (≥80% green, ≥50% primary colour, lower red) plus the topics you missed at the time. If you want to know "how am I actually doing in this course", that page is more useful than any single score.

### ③ Compress the whole book into revision cards

Click **AI Notes** at the top, then **Generate Notes**. It reads every document page by page and produces cards: core concepts, definitions, formulas, key points.

The cards can be:

- filtered with the search box ("Search note cards...")
- copied one at a time to the clipboard
- exported at once with **Download Study PDF** — the PDF is **searchable**, not a picture

Great for the week before an exam: read through the notes first, then use a quiz to check yourself.

### ④ Turn wrong answers into a study plan

After each quiz the results screen has three buttons: **Generate Wrong Answers Notes & PDF**, **Try Another Quiz**, **Generate Study Plan**.

- **Generate Wrong Answers Notes & PDF** builds revision cards for just the questions you got wrong this time, also exportable as a PDF. You can reopen them any time from the **wrong answers** panel on the right.
- **Generate Study Plan** opens a Markdown plan covering focus areas, a review strategy, active-recall tips and what to do next. It reads the wrong answers from your **last 5 quizzes**, so the more you test yourself, the closer the plan gets to your real weak spots.

The plan is **generated on demand** — nothing is sent to the model until you press the button, and the dialog also offers **Regenerate**.

## 📁 Uploading material

| Type | Extensions | Notes |
| --- | --- | --- |
| PDF | `.pdf` | **Scans work too**: every page is checked for a text layer and only the scans go through OCR; tables become Markdown |
| PowerPoint | `.pptx` `.ppt` | Slide by slide; the old binary `.ppt` works as well |
| Word (modern) | `.docx` | Body order preserved, tables flattened to `a \| b` |
| Word (legacy) | `.doc` | Natively supported — **no Word install, no extra dependency** |
| Markdown | `.md` `.markdown` | Headings, lists and code fences kept verbatim |
| Plain text | `.txt` `.text` | UTF-8 / GB18030 / UTF-16 detected automatically |
| Delimited | `.csv` `.tsv` | Split per row, with **the header repeated on every page** so a fragment still names its columns |

Maximum **500 MB** per file. Anything outside the table is rejected with a clear message.

A document has three states after upload: **Processing** (with a progress bar and a percentage) → **Ready** → ask away. If something goes wrong it shows **Failed** and the concrete reason.

### Why scanned PDFs still work

This is the easiest trap to fall into: plenty of PDFs are page-sized scans with no text at all, and an ordinary parser reads an empty string. In the past such a file would show **Ready** while not a single character had been indexed — so every question came back "not enough information".

It now happens in two steps: first **audit** every page (real text layer? page-sized image? blank?), then **OCR only the pages that need it**. The RapidOCR models ship inside the installer, so **it works offline and needs nothing else installed**.

Afterwards the document name carries a badge:

- `OCR 5p` — 5 pages were read by OCR
- `3p unread` — 3 pages were not read (past the page cap, for instance)
- `2p low conf.` — 2 pages were recognised with low confidence

Click the badge to open the **Parse report**, which shows how each page was read, where its text came from and what the OCR confidence was. **A clean digital PDF shows no badge at all** — no badge means everything is normal.

> A 1,400-page scanned book takes roughly 100 minutes to OCR end to end. There is no page cap by default, but for books that size it is better to upload in parts, or only upload the chapters you are revising.
>
> If a scan has OCR switched off *and* the machine has no OCR engine, the upload **fails outright with the reason** instead of pretending to succeed.

## ⚙️ Settings

Click **Settings** at the bottom of the sidebar (or press `Ctrl + ,`). There are only two panels:

**Language** — switch between English and 中文. The change takes effect immediately and applies to the interface text, the validation messages and the AI's answers alike. Ticking **Use as deployment default** also stores the choice as the default for every new visitor.

**API** — covered in ["Enter an API key"](#-up-and-running-in-5-minutes) above. Two extra points:

- The **Keys** menu beside the input is a small key safe: store several credentials, switch the active one at any time, delete the ones you no longer need. Keys are always displayed masked, as `sk-…128e`, never in the clear.
- After you change the base URL or the key, the green connection badge goes red — it only ever meant "that configuration worked when it was probed". Press **Connect** again to turn it green; the UI will not pretend it is still connected.

**The connection state is persisted.** Close the dialog and reopen it and both the green badge and the model list are still there. The connection shortcut in the sidebar reads the same state.

## ❓ FAQ

**Q: Every question comes back with "not enough information".**
First look for an `Np unread` badge next to the document name. If there is one, open the parse report — it is almost always a scan that could not be read. Re-upload it, or raise the page cap. It also helps to phrase the question in words closer to the source.

**Q: Uploading has been stuck on "Processing" for ages.**
Large files — especially scanned PDFs several hundred pages long — genuinely take a while. The progress bar shows the current stage (auditing pages / OCR / embedding…). If it runs past what you expect, check whether the document turned **Failed**; the reason is written there.

**Q: Where do I change the model?**
Settings → API → the model dropdown. The list is fetched live from the endpoint when you press **Connect**, and you can also switch to "enter a model name manually" and type your own.

**Q: Where is my data? Will uninstalling lose it?**
It installs to `%LOCALAPPDATA%\RagVault`; your documents and database live in `%APPDATA%\com.ragvault.desktop\data`. Uninstalling does not delete the data — delete that folder yourself to wipe everything (that is a full factory reset).

**Q: Does it need the internet?**
Generating answers, quizzes, notes and study plans needs the network (it calls a cloud model). **Parsing documents, embedding and retrieval all happen on your machine.** Only the snippets that retrieval actually hits are sent to the provider.

**Q: Does it upload my whole document?**
No. What leaves your machine is the few passages retrieved for this question, plus the question itself.

## 🛠 Running from source & building the installer

If you just want to use it, the sections above are all you need. The rest is for people changing the code.

### Requirements

| Need | Version |
| --- | --- |
| OS | Windows 10 1809+ / Windows 11 (WebView2 required) |
| RAM | 8 GB or more |
| Disk | 1.5 GB free (installer 168 MiB, about 402 MiB installed) |
| Toolchain | Python 3.11, Node 20+, Rust MSVC (only for building) |

### One-time setup

```powershell
python -m venv .venv-desktop
.venv-desktop\Scripts\pip install -r backend\requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

cd frontend
npm install --registry https://registry.npmmirror.com
```

To change a built-in default (model, chunk size, OCR parameters…), copy `.env.example` to `.env` and edit it.

> If downloading Python packages is slow, the `pip -i` and `npm --registry` flags above already point at mirrors, which is usually enough.

### Day-to-day development

```powershell
.\scripts\dev.cmd                 # API + Vite, both hot-reloading
.\scripts\dev.cmd -BackendOnly    # API only (also serves the built SPA)
.\scripts\dev.cmd -NoReload       # No hot reload, handy when using breakpoints
.\scripts\dev.cmd -Frozen         # Run the PyInstaller bundle — same binary as the installer
.\scripts\dev.cmd -Stop           # Stop every related process
```

The API comes up on `http://127.0.0.1:8000`, Vite on `http://127.0.0.1:3000`, and development data lands in `.desktop-data\` (completely separate from the installed app's data).

> **Why the entry point is `.cmd` and not `.ps1`**: `dev.ps1` is not code-signed, and on some machines the Authenticode verification path is restricted by security software, so running it directly fails with "not digitally signed" or "AuthorizationManager check failed". `dev.cmd` is not a PowerShell script, so the execution policy never applies to it; it launches `dev.ps1` with `-ExecutionPolicy Bypass` scoped to that one child process — no registry key written, no machine-wide policy changed. Arguments are forwarded verbatim, so both files behave identically.

To check behaviour that only exists in the desktop shell (native save dialog, first-run prompt, drag and drop):

```powershell
# Must be run from the repository root: the tauri CLI only searches downwards
# for tauri.conf.json, so running it inside frontend\ fails.
.\frontend\node_modules\.bin\tauri dev
```

`tauri dev` does not hot-reload the frontend (the window loads the built bundle from `frontend\dist\`), so rebuild with `npm run build` and restart the shell after a UI change. Day-to-day UI work is much faster with `dev.cmd`.

### Building the installer

```powershell
# 1) Frontend first — the spec packs frontend\dist into the frozen output
cd frontend; npm run build

# 2) Freeze the backend (~5 min, ~397 MB output)
.venv-desktop\Scripts\pyinstaller backend\ragvault-backend.spec

# 3) Build the installer (needs a proxy for the first NSIS download)
$env:https_proxy="http://127.0.0.1:7897"
frontend\node_modules\.bin\tauri build
```

Step 2 collects `frontend/dist` into `dist\ragvault-backend\_internal\frontend\dist`, so **the frontend must be built first**; after a frontend change just rerun steps 2 and 3 — there is nothing to copy by hand. The output lands in `src-tauri/target/release/bundle/nsis/`.

### Running the tests

```powershell
cd backend
pip install -r requirements-dev.txt
pytest tests/ -q

cd ..\frontend
npm run lint
```

`backend/tests/conftest.py` uses in-memory SQLite, so no external service is required. Current size: **141 tests** (auth, every format parser, the PDF pipeline, ingestion progress, the Chroma guards, connection-state persistence, JWT key handling).

> `conftest.py` pins `JWT_SECRET`. Without that, every test run would leave a `.jwt_secret` file in the repository.

## 🧱 Technical notes

### Runtime shape

| | Desktop |
| --- | --- |
| Startup | Double-click the exe (the Tauri v2 shell launches the backend) |
| Backend | One Python process, listening on `127.0.0.1` only, on a fixed port |
| Database | SQLite (WAL) |
| Vector store | Embedded ChromaDB (PersistentClient, one collection per knowledge space) |
| UI | Native WebView2 window, SPA served by the backend |
| Data location | `%APPDATA%\com.ragvault.desktop\data` |
| Install location | `%LOCALAPPDATA%\RagVault` |
| Upload cap | 500 MB |

The port is **stable across launches** (the last port that bound successfully is remembered in `<data>/app-port.txt`, falling back through `47823–47826` if it is taken). That is not just tidiness: WebView2 partitions `localStorage` by origin, so a changing port would reset the theme, the language and the login state back to factory defaults.

### Architecture

```
Tauri v2 shell (Rust)
   │  generates RAGVAULT_LOCAL_TOKEN, spawns the backend, parses RAGVAULT_READY port=…
   ▼
WebView2 window (React + Vite, served by the backend)
   │  REST + SSE  │
   ▼               ▼
FastAPI backend (single Python process, bound to 127.0.0.1)
   ├── Auth (JWT)
   ├── Ingestion    parse → chunk → embed → ChromaDB
   ├── RAG service  (LangGraph) question → retrieve → LLM → answer + citations (SSE)
   ├── Quiz service parallel batch generation → grading → weak topics
   ├── Notes service page-by-page cards → downloadable PDF
   └── Recommendation service (LangGraph) → personalised Markdown study plan
```

| Layer | Technology |
| --- | --- |
| Frontend | React 18 + Vite + TypeScript + Tailwind CSS + shadcn/ui |

### Design tradeoffs

A few deliberate choices, written down so they are not mistaken for bugs later:

- **A page with a real text layer is never OCRd.** The text layer is exact; OCR could only be worse.
- **No parallel OCR, but the thread count is capped.** onnxruntime opens one thread per logical core by default, and under load those threads fight for cores: measured on the same pages, the library default took 12.4 s/page and a cap of 8 took 7.5 s/page. The count is controlled by `PDF_OCR_THREADS` (default 8), and long documents are bounded by `PDF_OCR_MAX_PAGES` and `PDF_OCR_TIME_BUDGET_SECONDS`.
- **OCR at 300 DPI with the long edge capped at 1600.** At 400 DPI the character count and confidence were identical — just slower.
- **CSV repeats its header on every page.** A fragment cut from the middle of a table with no header is just bare numbers and retrieves nothing.
- **`.doc` is implemented in-house rather than pulled in as a dependency.** `python-docx` cannot read Word 97-2003; `olefile` is another package to vendor, COM requires a licensed Word install, and `textract`/`antiword` bring native binaries. `backend/app/utils/doc_legacy.py` implements the CFB container and the Word piece table in pure Python.
- **No automatic remedial parallelism for documents.** CPU contention would slow down work that should be fast; better to show the user honest progress.

### Environment variables

Day-to-day use needs no configuration file at all — the API key, language and model live in the in-app Settings dialog and are stored in the local SQLite database. The variables below are only the built-in defaults, overridable from `.env` during development (see `.env.example`):

| Variable | Default | Description |
| --- | --- | --- |
| `LLM_PROVIDER` | `deepseek` | `deepseek` / `openai` / `custom` |
| `LLM_API_KEY` | *(empty)* | Leave blank and enter it in the app |
| `LLM_MODEL` | `deepseek-chat` | Model identifier sent to the provider |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI-compatible base URL |
| `LLM_TIMEOUT_SECONDS` | `180` | Per-request timeout |
| `LLM_MAX_RETRIES` | `3` | Retries on 429 / 5xx / transport errors |
| `APP_LANGUAGE` | `en` | Built-in default UI + AI language (`en` / `zh`) |
| `ENABLE_OCR_UPLOADS` | `true` | OCR for PDF scans; also unlocks the shelved image OCR |
| `PDF_OCR_ENGINE` | `auto` | `auto` / `rapidocr` / `tesseract` |
| `PDF_OCR_DPI` | `300` | Rasterisation DPI |
| `PDF_OCR_MAX_SIDE` | `1600` | Long-edge cap on the rendered image |
| `PDF_OCR_MAX_PAGES` | `0` | Max pages OCRd per document (`0` = unlimited) |
| `PDF_OCR_TIME_BUDGET_SECONDS` | `1800` | Per-document OCR budget |
| `PDF_OCR_MIN_CONFIDENCE` | `0.75` | Pages below this are flagged low-confidence |
| `PDF_OCR_MAX_ATTEMPTS` | `3` | Preprocessing ladder depth |
| `PDF_OCR_THREADS` | `8` | ONNX threads for OCR (`0` hands the choice back to the library) |
| `PDF_MIN_TEXT_CHARS` | `200` | A page-sized image with less text than this needs OCR |
| `PDF_EXTRACT_TABLES` | `true` | Convert PDF tables to Markdown and index them too |
| `EMBEDDING_MODEL` | `BAAI/bge-small-en-v1.5` | FastEmbed ONNX embedding model |
| `CHUNK_SIZE` | `600` | Target tokens per chunk |
| `CHUNK_OVERLAP` | `100` | Token overlap between chunks |
| `TOP_K` | `5` | Number of chunks retrieved per query |
| `DATA_DIR` | `%APPDATA%\com.ragvault.desktop\data` | Root for all mutable data |
| `JWT_SECRET` | *(empty → generated)* | Left empty, the first start generates one per install into `<data dir>/.jwt_secret` and reuses it. Set it only to force a shared key (≥32 chars) |

### Pointing it at a different provider

Answer generation is an ordinary OpenAI-compatible HTTP call, so it can point at any compatible server — including a vLLM / llama.cpp / Ollama gateway on another machine:

```bash
LLM_PROVIDER=custom
LLM_BASE_URL=http://192.168.1.10:11434/v1
LLM_MODEL=qwen2.5:7b-instruct
LLM_API_KEY=not-needed-but-must-be-non-empty
```

`LLM_API_KEY` must be a non-empty string even for a keyless local server, because the client refuses to send unauthenticated requests.

### Troubleshooting

```powershell
.\scripts\dev.cmd -Stop     # Stop every related process

# Factory reset (documents and accounts included)
Remove-Item -Recurse "$env:APPDATA\com.ragvault.desktop"
```

Desktop logs are forwarded by the Tauri shell to the console that launched it; during development you see the backend output directly in `dev.cmd`.
